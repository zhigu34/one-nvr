# one-nvr 功能总结（截至 2026-10-11）

本文面向「想快速了解系统已经能做什么、每个模块内部是怎么做的」的读者。范围以 P0 已交付为限，每节给出功能清单与关键实现逻辑；明确未实现的内容单列在文末，避免「容器在跑」被误读成「业务可用」。

系统定位：单站点、本地部署的 16–32 路固定通道 NVR。Go + PostgreSQL 管理配置/任务/索引，ZLMediaKit（ZLM）负责取流与录像落盘，React（shadcn-admin）管理界面；可选 Frigate（检测）与 OpenList/WebDAV（云归档）模块。

---

## 1. 通道与摄像头接入（CH）

**功能**
- 16/32 个固定槽位（CH01…），通道 ID 与编号终身不变；换摄像头只是换「源版本」，历史录像、权限、策略、归档全部留在通道上。
- 添加方式两种：RTSP 手动；ONVIF 手动（不做局域网扫描）——填 IP/ONVIF 端口/凭据，主/子码流由设备返回并自动填充，凭据不落盘明文。
- 通道管理页：名称/分组/启停（停用只停取流录像，不动配置与历史）、媒体参数列（分辨率/编码/帧率/音频，来自最近一次成功测试）、接入方式列、最近错误、一次请求的批量摘要（`GET /channels/summary`）。
- 「保存并启用」：保存配置 → 真实测试（认证/视频轨/编码/分辨率/首帧）→ 测试通过才应用为新源版本；失败可重试且保留凭据。

**关键逻辑**
- 源配置版本化：每次修改产生新版本（修订），`current_revision_id` 指向生效版本；换源带预检与回滚，配额语义上「配置保存」与「启用」是两件事。
- ONVIF 探测在 5 秒预算内完成：先匿名取设备时间校准时钟，再签 WS-UsernameToken 摘要（解决设备时钟漂移导致的认证拒绝）；只取路径不跟随设备给的地址（防 SSRF）；结果拆成结构化字段（IP/端口/路径），凭据丢弃且不进响应与审计。
- 地址边界：探测与保存共用同一 `ONE_NVR_CAMERA_CIDRS` 白名单与错误码。

## 2. 实时预览（Live）

**功能**
- 1/4/9/16 宫格 WebRTC 直播（WHEP），主/子码流切换；瓦片底栏显示浏览器实测的分辨率/帧率/「直通」/音频编码；非 16:9 画面按实际比例自适应、单瓦片全屏切换。
- 权限按通道（`live` grant）；未授权通道在列表与播放两层都被屏蔽。

**关键逻辑**
- 实时链路从不转码：ZLM WHEP 只做协议打包，不支持的编码（如 H.265）在接入测试时即拒绝并提示改 H.264；「直通」如实反映未转码。
- 媒体信息来自浏览器 `RTCPeerConnection.getStats()`（2s 采样），不依赖服务端推断。
- 音频轨竞态已修：answer 带音频 m-line 触发第二次 `ontrack` 会打断 `play()`，现每会话只赋值一次 `srcObject`、后续只 `addTrack`。

## 3. 录像（REC）

**功能**
- 录像计划页（侧边栏一级菜单）：按通道选择录像方式（手动＝连续录像；定时/事件为占位禁用），支持批量应用与存储池绑定检查。
- ZLM 60 秒 MP4 分片，命名规则 v3：`通道号_本地开始时间_录像ID.mp4`；分片完成 → 持久化发布意图 → 原子移动到正式目录 → 索引可播。
- 分片状态机：`provisional`（绝对时间待确认）→ `ready`（可播可归档）→ `finalizing/missing/damaged/conflict/deleted`；文件与发布记录不一致自动隔离为 damaged/missing，不静默吞掉。

**关键逻辑**
- 发布是崩溃安全的：完成回调先进 `hook_inbox` 收件箱（持久化），发布在单事务里移动文件+改状态+登记位置；中断后由恢复循环重放。
- 发布时用 ffprobe 采集媒体证据（编码/分辨率/帧率/时长）入 `media_evidence`，回放列表与导出参数校验直接复用，零二次探测。
- 录像计划与通道策略（手动/定时/事件）解耦：接入只取流，`first_recording_mode` 固定 none。

## 4. 回放（PLAY）

**功能**
- 「录像」工作区（回放 / 录像管理两页签，通道与时间上下文共享）：按站点时区检索、时间轴（片段单击选中/双击播放/拖动定位）、±10 秒、0.5–4 倍速（跨片段保持）、下一可用片段、缺口提示。
- 检索索引按 `next_cursor` 翻页取全窗口（每页 500、上限 2000 段），触顶显式警告，**未取回的页不会被伪装成缺口**。
- 授权字节读取：`GET /recordings/{id}/content` 单区间 Range 交付（206/416 语义正确），审计先于第一个媒体字节；未授权与不存在不可区分（都是 404）。

**关键逻辑**
- 缺口 = 已取回片段覆盖之外的真实索引空洞；换源重叠按最早起点取一份，不重复播放。
- 空闲状态不显示伪位置（epoch 0 曾渲染成 1970-01-01）；时间轴红线首次播放前不渲染。
- 站点时区是唯一显示口径：检索、时间轴、列表全部按 `GET /site` 返回的 IANA 时区解释（`zone.ts` 单点换算）。

## 5. 录像文件管理与生命周期（FILE）

**功能**
- 录像管理页（管理员）：按通道/时间/源版本/存储池/文件健康/归档/保护筛选；摘要（片段数/时长/逻辑大小/已删除释放）；批量删除本地副本（逐项结果 + 释放字节）；行内「本地+云端」徽标。
- 保护两态：单段开关（PATCH）+ 按时间窗口批量保护（`POST /recordings/protect-window`）；受保护片段自动清理与删除都跳过。
- 保留策略：站点级天数，**默认 0＝不自动删除**；跳过受保护与发布不足 10 分钟的片段。

**关键逻辑**
- 删除顺序＝先 unlink 后改状态：崩溃只会留下「索引 ready、文件已不在」，由既有对账标 `missing`——主动删除（`deleted`）与外部消失（`missing`）严格区分（PRD FILE-04）。
- 删除被三类引用拦截并给逐项理由：导出任务 pin（`pinned_by_export`）、上传中的归档副本（`archiving`）、受保护（`protected`）。
- 位置维度区分「本地 / 本地+云端 / 仅云端 / 暂不可用 / 已删除」，健康与归档是独立维度（FILE-02）。

## 6. 范围导出与证据（EXP / FILE-06）

**功能**
- 回放页选中片段 →「导出」：先做范围分析（可导出时长/缺口/暂不可用片段/参数一致性预览），选缺口处理（合并为单一文件 / 按连续区间分段），提交后对话框跟踪进度并直接下载。
- 录像管理页「导出记录」抽屉：进度、失败原因、到期时间、下载 ZIP/MP4、admin 保护开关。
- 证据 ZIP：`manifest.json`（任务、创建人反规范化、通道、请求与实际窗口、缺口、每个产物的 SHA-256 与源分片列表——不含文件系统路径）+ 原始 MP4。

**关键逻辑**
- 异步任务复用 jobs 基座：并发 2、每页游标翻页、崩溃重跑从零开始（工作目录重建），产物原子发布后单事务登记，无半成品可见。
- 只做原码拼接（ffmpeg concat `-c copy`）：片段 `media_evidence` 视频参数全等才拼，不一致直接失败（`media_incompatible`），不静默转码；产物完成后 ffprobe 校验时长容差。
- 任务保护：创建即 pin 源分片，删除路径在任务期间拒绝（EXP-05）；产物默认 7 天到期，admin 可永久保护；下载先审计后出字节。

## 7. 存储池（STO）

**功能**
- 目录池注册（路径身份用 marker 固化，拒绝重复注册同一目录）；池状态、占用、最近检查；停用/删除语义（有引用只能停用）。
- 写入证据：`api`/`worker` 双健康检查 + 真实摄像头写探针；录像绑定/启用要求新鲜证据，页面遇证据过期自动补检查重试（用户裁决：一切顺利操作）。

**关键逻辑**
- 容量闸：发布与导出都读 `storage_pool_checks` 的新鲜 `free_bytes`；停录看门狗在「关闭写入检查」之外始终兜底——写不进就停录并记缺口。
- 对账：列表与用量校验打开每个 ready 文件核对身份（device/inode/size/mtime），不一致置 `damaged`，消失置 `missing`。
- 所有文件操作经 `os.Root`（O_NOFOLLOW 逐段校验），发布用 renameat2 no-replace + 目录 sync。

## 8. 云归档（ARC，M2.1 进行中）

**已交付（批次 1–2）**
- WebDAV 目标管理（admin）：名称/URL/根目录/账号/密码（复用源凭据加密，AAD 绑定目标 ID）；探针验证写入、读取、Range、删除四项能力并记录，缺删除如实显示「到期清理不可用」；有副本引用的目标只能停用。
- 通道归档策略：手动 / 立即上传（发布事务内自动入队，hook 失败不影响发布） / 定时上传（站点时区每日时刻，账本 UNIQUE 去重防多实例重复，单次触发补扫全部未归档分片 ≤100）。
- 上传管线：远端对象键＝`<站点ID>/recordings/<通道号>/<本地日期>/<与本地同名文件>`（共用录像 ID 与冻结命名）；流式 PUT 顺便计算 SHA-256；完成后 Content-Range 长度验证才标「已归档」；不可达走退避重试，凭据类失败永久终止。
- 副本索引：`recording_archive_copies`（状态/大小/哈希/验证时间）；上传中的源分片被删除保护拦截（理由 `archiving`）；管理页「本地+云端」徽标。

**批次 3 待做（ARC-04/05/07/09）**：仅云端 Range 回放代理、本地安全清理（48h 默认+播放租约）、云端到期清理（365 天默认+保护例外）、远端对账与缓存、云源导出。

## 9. 权限、审计与安全

**功能**
- 三角色（管理员/操作员/查看者）+ 通道级授权五动作：`live` / `playback` / `export` / `configure` / `archive`；操作员默认无上传权，管理员全链默认拥有。
- 所有写操作：CSRF + Origin 校验、`If-Match` 版本条件（并发写冲突 409）、幂等键（导出/删除/上传/任务类端点重放安全）。
- 审计：账号/通道/源/录像/导出/归档的关键状态变化逐条落 `audit_logs`；负载经 safejson 消毒（密码/token/URL 形态的键值拒收）；WebDAV 与源凭据只存密文。

**关键逻辑**
- 越权与不存在统一 404（不泄露存在性）；会话撤销即时生效（grants 带 auth_version，任务领取时校验）。
- 批量操作部分成功语义：逐行结果、被拒行给理由、不回滚已接受行。

## 10. 部署、运维与质量门

**功能**
- `./deploy.sh` 单入口：环境探测、密钥初始化、Compose 渲染；基础 5 容器（api/worker/zlm/gateway/postgres），可选 Frigate/MQTT 与 OpenList。
- 证书：上传/预检/应用/回滚 + 目录续签自动应用（外部续签目录内容变化自动检测并热切换）；HTTP/HTTPS 入口协议切换。
- 运维页：组件健康观测、作业状态、审计检索；硬件探测（CPU/核显/NVIDIA）驱动可选转码档案。
- CI（GitHub Actions）11 个 job：单测（-race）、迁移并发/校验和、网关 TLS、真实浏览器直播/回放、合成摄像头真实容器媒体验收、生产运行时、硬件路径、镜像构建。**真实媒体验收只能在 CI 跑**，本机无 Docker。

- 智能与事件（M3）：区域规则、检测事件、通知、抓拍归档——Frigate 容器存在不代表业务可用。
- 云归档批次 3（M2.1 收尾）：本地安全清理+播放租约、仅云端回放、云端到期清理、远端对账、云源导出。
- 容量压力淘汰与通道配额（STO-02/03，依赖归档安全副本语义）。
- 导出精确裁剪（转码）、长时段自动拆分；录像定时/事件计划（现仅占位）；16–32 路并发容量认证；现场两台 NAS 的长期稳定性记录。

- 待现场确认：两台 NAS 的最新部署验证、真实 WebDAV 端点（OpenList）探针与上传、长期录像连续性与容量表现。
