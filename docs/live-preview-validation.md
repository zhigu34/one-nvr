# 实时预览验证

在通道配置中填写摄像头连接信息，点击“保存并连接”自动检测并应用，随后打开“实时预览”，选择画面并点击通道。首次接入只启用预览，不需要存储池；需要录像时在“录像设置”中选择存储池并开启录像。修改已有摄像头会保留原录像策略，连续录像的存储池检查会自动执行。高级连接设置中仍可“仅保存并测试”，诊断区保留单独测试与应用。

支持 1/4/9/16 分屏、32 路通道分组、主子流切换、全屏、停止、拖拽排序与浏览器内保存布局。默认静音，只有选中画面可以启用声音。缺少子流配置时提示回落到主流；已配置但离线的子流不静默切换。标签页进入后台暂停，返回后重新协商。连接失败最多自动重试三次，编码不支持时提示改为 H.264。

浏览器只调用同源授权 API；不获取摄像头账号、ZLM 管理凭据和删除令牌。播放票据绑定登录会话、通道与物理源流。租约30秒、每10秒续租；续租不会刷新登录闲置期限。Worker每2秒扫描过期/撤销/换源状态；删除失败留存并延后重试。预览不会创建录像任务或摄像头代理。

部署沿用根目录 `./deploy.sh`，无新增容器或 `.env` 参数。`ONE_NVR_MEDIA_HOST` 必须是浏览器能够直连的宿主机地址，`ONE_NVR_RTC_PORT` 的 UDP/TCP 端口须可达；8443 只负责网页与信令，视频走 RTC 端口。WebRTC 接收不读取本地摄像头，可在 HTTP 或 HTTPS 入口使用。

## 现场部署检查

更新当前开发分支并执行根目录 `./deploy.sh`。沿用已有数据目录、端口、密钥和通道，无需重新初始化站点。

1. 在“通道管理”中选一路现有摄像头，点击“保存并连接”，确认主流/子流状态正常。
2. 打开“实时预览”，选一个画面，再点击左侧通道。确认出现持续变化的视频；“播放中”只在收到实际帧后显示。
3. 切换主流和子流，确认视频恢复。未填写子流时默认回落主流，并显示原因。
4. 将该通道录像模式设为“关闭”并应用，确认预览仍可使用；这一步会停止该通道后续录像，测试后按需恢复原模式。
5. 点击停止或切换到其他页面，再返回预览；切到后台后预览暂停，返回时重新连接。

如果提示“通道流未就绪”，检查配置是否已经应用、摄像头是否在线。编码提示不支持时将对应摄像头码流改为H.264。网页可打开但一直连接超时，则核对 `.env` 中 `ONE_NVR_MEDIA_HOST` 是否能从当前浏览器直达，以及 `ONE_NVR_RTC_PORT` 对应UDP/TCP端口是否放行；网页8443端口可访问不代表RTC视频端口可访问。
