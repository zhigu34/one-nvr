# one-nvr 访问方式与 TLS 证书管理

版本：1；日期：2026-10-04。正式版设计，尚未实现。范围为自带 gateway 的 HTTP/HTTPS 入口与手动证书管理；不修改现有 M0 HTTPS 实验包。

## 1. HTTP 与 HTTPS

默认使用 HTTPS，允许部署者选择 HTTP。入口协议直接取 `ONE_NVR_PUBLIC_URL` 的 scheme，不增加重复的协议开关。首版只运行选定的一种业务入口，不额外引入 HTTP/HTTPS 并行登录或自动跳转设置。

| 参数 | 规则 |
| --- | --- |
| `ONE_NVR_PUBLIC_URL` | 必须是有效 http 或 https URL，主机为部署者使用的域名/IP，不含用户信息、query 或 fragment；根路径入口 |
| `ONE_NVR_HTTP_PORT` | HTTP 模式的宿主入口端口，默认 8080 |
| `ONE_NVR_HTTPS_PORT` | HTTPS 模式的宿主入口端口，默认 443，可指定 8443 |
| `ONE_NVR_RTC_PORT` | 独立的实时媒体端口，默认 8000，同时用于 UDP/TCP；不得与当前活动业务入口的 TCP 端口冲突 |

启动工具根据 URL scheme 选择对应端口与 gateway 配置，只绑定所选入口。PUBLIC_URL 的有效端口必须与所选端口一致；URL 省略端口时按协议默认端口 80/443 解析，不自动把 http://host 改成 host:8080。未选协议的端口配置不要求占用/探测，HTTP 模式不要求已配置有效 TLS 证书。

HTTPS 示例：

```dotenv
ONE_NVR_PUBLIC_URL=https://192.168.1.10:8443
ONE_NVR_HTTPS_PORT=8443
ONE_NVR_RTC_PORT=8000
```

HTTP 示例：

```dotenv
ONE_NVR_PUBLIC_URL=http://192.168.1.10:8080
ONE_NVR_HTTP_PORT=8080
ONE_NVR_RTC_PORT=8000
```

协议/端口是容器部署参数，修改后执行 deploy.sh，更新 gateway 的监听和端口映射；仅网关入口变更不重建 ZLM。RTC 参数变更按原媒体维护规则处理。证书上传/替换属于界面操作，不要求编辑 .env；在 HTTP 模式上传的证书保存为 HTTPS 待用配置，不凭上传动作自动更换浏览器 URL 或 Docker 端口。

HTTP 页面明确显示“当前连接未加密”，账号与权限仍正常校验。服务器端会话 Cookie 始终包含 HttpOnly/SameSite/Path；HTTPS 请求包含 Secure，已明确选择 HTTP 的部署不设 Secure，否则浏览器无法维持登录。API 只相信自带 gateway 覆写的协议信息，不能由客户端任意 X-Forwarded-Proto 降级。入口协议切换撤销原会话，重新登录；不因上传证书撤销普通会话。

仅接收远端视频的播放器不调用 getUserMedia，不因为使用 HTTP 就预先宣告所有 RTC 预览失败，Chrome/Edge 兼容性须真机验证。本地摄像头/麦克风采集受浏览器安全上下文约束，未来双向对讲按 window.isSecureContext 和实际 API 可用性检查并提示限制；普通局域网 HTTP 不承诺具备这些能力。HTTPS 的媒体代理/信令仍使用同源入口，不能生成混合内容 URL；网页协议选择不改变独立 RTC 媒体端口。

## 2. 系统设置 → 访问与证书

管理员可查看当前访问协议、入口 URL、当前监听端口以及自带 gateway 的证书状态。页面提供：

- 上传证书链与对应私钥、预检结果、应用证书、替换证书及切回保留的上一有效版本。
- 查看当前生效版本、已上传未生效版本和上一次应用结果；HTTP 模式明确标记“HTTPS 未启用”，不把待用证书显示为正在提供 TLS。
- 显示证书类型（自签/导入）、主体/CN、签发者、SAN 域名/IP、序列号、有效起止、剩余天数、SHA-256 指纹、公钥算法和位数。
- 显示正常、30 天内到期、7 天内到期、已过期、尚未生效、主机不匹配、应用失败等独立结果。日期按站点时区展示，判断基于绝对时刻。到期提示进入运维记录，不修改录像保留期限。

页面/API 不返回私钥，也不提供私钥下载。自签证书或企业 CA 是否受某个浏览器信任不能由证书解析保证；页面显示来源和校验事实，不把“已应用”标成“所有客户端已信任”。只管理自带 gateway，外部反向代理自己的证书由其部署环境管理。

## 3. 导入、预检与持久化

首版支持 PEM 格式服务器证书/fullchain（.pem/.crt）与未加密 PEM 私钥（.pem/.key）；内容解析决定有效性，不仅检查扩展名。支持常规 RSA/EC 证书及 PKCS#1/PKCS#8 私钥；组合上传最大 1 MiB。其他格式或加密私钥明确提示不支持，不悄悄忽略。私钥与证书链不会进入审计正文、日志、URL、前端持久缓存或普通配置导出。

上传预检包含 PEM/X.509 解析、证书/私钥公钥匹配、证书链顺序/签名一致性、服务器证书用途、有效期和入口主机 SAN 匹配。入口为 IP 时检查 IP SAN；域名检查域名 SAN，不以“CN 看起来相同”替代。未提供可用链或有效证据时给出具体结果，不能伪造客户端信任。

允许匹配入口的自签服务器证书；单张自签证书不因缺少公共 CA 链被拒绝。导入 fullchain 校验提供的相邻证书签名与顺序，根证书可省略；不要求导入企业 CA 已在服务器或所有浏览器的信任库中。链完整性、证书用途与客户端信任分别报告。

解析后保存不可变证书版本、公共元数据和私钥文件引用。私钥位于持久化 `ONE_NVR_DATA_DIR/tls/versions/<certificate_id>/` 的受限目录，只有必要服务可读取；不放录像池、不由静态网关公开、不随镜像分发。首次 HTTPS 初始化没有导入证书时生成带入口 SAN 的自签证书一次，重建容器不重新生成；普通重新部署不能因证书异常覆盖用户证书。

上传有效不等于已应用。应用时再次检查当前入口及有效期；过期、尚未生效、主机不匹配或密钥不匹配不替换当前证书。当前证书到期则如实报告，不自动改为 HTTP、不自动替换证书。管理员可在页面明确选择已有有效版本；当前使用或任务引用中的版本不能删除。

## 4. 在 gateway 容器内执行应用

API/Worker 与 gateway 分容器，不能在 API 里执行 nginx 命令来假装已重载另一个容器。复用现有 gateway，在其中增加受限的证书应用控制进程；不新增常驻容器，不挂 Docker socket，不给 API 控制整个 Docker 的能力。

Worker 将持久任务的 certificate_id、job_id、预期当前版本写入专属共享控制目录；gateway 控制进程只处理已定义的证书应用请求，不能接收任意 shell、命令参数或路径。路径由版本 ID 在固定 TLS 根内解析，拒绝越界。控制目录和证书文件不暴露为 Web 静态资源。

应用顺序：

1. 持久化待应用任务和上一有效版本，互斥处理同一网关的证书操作；Worker/gateway 重启按任务记录对账。
2. 准备目标证书与受控候选配置，在 gateway 内执行 nginx -t 检查；失败保留旧配置/证书并返回具体错误。
3. 原子切换配置引用并发送 reload，随后通过新的 TLS 连接核对自带 gateway 的实际叶证书 SHA-256 指纹，不能仅凭命令返回成功判为生效。
4. 指纹一致后记录生效版本/时间，成功审计只保存公共摘要；reload、探测或最终提交失败时保留任务证据，恢复/回滚到上一有效配置并再次核验，不伪报成功。

启动控制流程先对账中断的应用意图，避免崩溃后只按一个半更新引用启动。HTTP 模式不执行 TLS reload/握手探测，只保存已验证待用版本；切换到 HTTPS 时按部署流程检查该版本。证书任务不调用 ZLM 重启/停止录像，也不重建 API/Worker。验收以实际持续录制和新连接证书为准，不把网关 reload 等同于“所有客户端连接完全无变化”。

## 5. M1 交付与验收

入口选择、证书页面/导入和受限 gateway 应用控制在 M1-A，实际浏览器媒体兼容和不中断录像验证在 M1-C。手动证书更新纳入首版；自动 ACME 申请/续期不在本轮范围。

- HTTP/HTTPS 的登录、Cookie 属性、同源/CSRF 校验及入口切换后重新登录；非法 URL/scheme/端口/冲突拒绝部署，未选协议不占端口。
- HTTP 无证书也可启动；HTTPS 自签首次生成且重建保留，证书私钥不公开；页面正确区分 HTTP、待用、有效及到期状态。
- 正常 fullchain/key、错误密钥、链顺序、IP/域名 SAN、过期/未生效和超大文件；上传失败不替换当前版本，私钥不出现在响应/日志/导出。
- 成功 reload 用新 TLS 连接验证真实指纹；故障、重复请求、预期版本冲突及应用中重启可恢复，回滚核验可观察。两路 ZLM 原有录像持续产片，不因更新证书重启。
- Chrome/Edge 分别验证 HTTP 下的远端接收预览、HTTPS 下的预览/回放和 API；麦克风采集能力按浏览器实际安全上下文提示，不把规范推论称为测试通过。

## 官方依据

- [W3C WebRTC](https://www.w3.org/TR/webrtc/) 与 [Media Capture and Streams](https://www.w3.org/TR/mediacapture-streams/)：远端连接与本地设备采集是不同接口，MediaDevices/getUserMedia 受安全上下文约束。本项目由此不预先统一禁用 HTTP 接收预览，这是设计推论；浏览器支持范围仍需实测。
- [Nginx HTTPS 配置](https://nginx.org/en/docs/http/configuring_https_servers.html)：证书/密钥和证书链配置。
- [Nginx 配置测试参数](https://nginx.org/en/docs/switches.html)、[重载流程](https://nginx.org/en/docs/control.html)：预检与优雅 reload 原语，不能代替实际指纹及业务连续性验收。
