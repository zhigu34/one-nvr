# M0 Compose Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. The user requested direct implementation in this session after reviewing the PRD and M0 checklist.

**Goal:** Deliver a Linux Docker Compose M0 package the user can deploy with two real cameras.

**Architecture:** ZLM owns upstream camera connections and MP4 recording. Frigate consumes ZLM RTSP with recording disabled; a small Python probe persists MP4 hooks and MQTT events in SQLite and serves an authenticated temporary verification page. A bootstrap command generates persistent secrets, upstream configuration and camera mapping from the agreed eight-column CSV.

**Tech Stack:** Docker Compose, ZLMediaKit, Frigate 0.17.2 candidate, Mosquitto, Python 3.12, SQLite, Nginx.

**Spec:** docs/PRD.md v0.14 and docs/M0-validation.md.

## Global Constraints

- Single-host Linux x86_64, EPYC CPU or N5105 Intel GPU profile.
- Production camera CSV: channel_no,channel_name,ip,rtsp_port,username,password,main_path,sub_path; optional onvif_port. Current M0 Compose uses full camera URLs in .env as subsequently requested.
- ZLM is the sole official recorder; Frigate record disabled and snapshots enabled.
- M0 is a probe, not the completed production control plane; SQLite replaces PostgreSQL only in this isolated experiment.
- No cloud upload/automatic media cleanup or full source-switch workflow is implied by this deployment.
- Upstream image pins and actual pulled image digests are recorded; the tool image uses `python:3.12-slim` as explicitly requested by the user. No existing secret is overwritten by repeated initialization.

## Review Focus

- Special characters in passwords/query strings must survive URL/config generation without leaking into the page.
- Repeated setup must preserve secrets and recordings; camera changes need a documented stop/reconfigure/start flow.
- Hook paths must resolve inside the shared storage root, never to arbitrary host files.
- Late/duplicate MQTT updates and MP4 hooks must not duplicate logical entries or reopen ended events.
- Missing camera/GPU, failed pulls and unsupported media must surface as errors rather than be reported healthy.
