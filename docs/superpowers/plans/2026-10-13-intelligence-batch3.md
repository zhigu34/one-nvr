# M3 智能与事件批次 3：区域、规则与误报标记

**Goal:** 让「哪个区域、什么目标、什么时段、什么级别、怎么告警」可配、可回滚、可验证——完成 PRD 的 M3 出口条件「事件到录像和证据闭环，配置可回滚」。

**Spec:** PRD AI-02（区域编辑）、AI-03（规则类型）、AI-04（规则条件）、AI-06（规则预览与误报标记）、AI-05（去重，本批只做规则维度）。

## 职责边界（先说明，避免误解）

**one-nvr 不做区域判定**。判定（`inertia` 防抖、`zone_score` 累计、停留阈值）全部由 Frigate 承担，one-nvr 只做三件事：

1. **把区域定义传给 Frigate**——归一化多边形写进 `config.yml` 的 `cameras.<name>.zones`
2. **把 Frigate 的判定结果读回来**——事件里的 `entered_zones` 已入库（批次 1），本批用于规则匹配
3. **在事件之上做业务规则**——按区域/类别/时段/级别筛选并生成逻辑告警

PRD AI-03 明确禁止「用目标框任意相交冒充 Frigate 的 zone 语义」，因此绝不自行计算几何相交。

## 范围

### 1. 区域定义（AI-02）
- 每通道多区域：名称、归一化多边形坐标（0–1，相对检测画面）、关注目标类别
- 校验：至少 3 个顶点、多边形自交拒绝、坐标范围、名称唯一且非空
- 视角/比例变化：记录绘制时的流几何（`reference_width/height`，**由服务端从该通道的 source test 读取，不接受客户端提供**），几何比例不一致则提示「待校准」，**不自动改坐标**（改坐标等于替操作者猜测）
- **判定口径**：Frigate 把每路源流拉伸进它自己的固定检测帧（`frame_shape = detect.height/width`），所以归一化坐标天然对分辨率免疫；只有**源流画面比例变化**（换码流配置、传感器旋转、换镜头）才会让同一组坐标落到不同场景位置——那才是「待校准」的条件。两侧任一未知（从未测试成功）时不报警，不凭空制造漂移
- 发布时写进 `config.yml`：`zones: {<zone_name>: {coordinates: "x1,y1,x2,y2,...", objects: [...]}}`
- **画布取帧**：`GET /api/v1/detection/frame`（configure 权限）代理 Frigate 的 `/{camera}/latest.jpg?height=360`，即检测器实际分类的那一帧。不从摄像头抓快照：那是另一路流、另一个尺度，镜头或码流配置一变视野就不同，画在上面的多边形描述的不是检测器看的像素

### 2. 规则（AI-03/04）
三类规则，映射到 Frigate 的既有语义：
| one-nvr 规则 | Frigate 对应 | 说明 |
| --- | --- | --- |
| 目标出现 | 无区域条件的对象事件 | 只要该类别出现即告警 |
| 区域进入 | `entered_zones` 包含该区域 | 用 Frigate 的进入判定，不用相交 |
| 区域停留 | Frigate 的 loitering（区域 + 时间阈值） | 阈值渲染进 `zones.<名称>.loitering_time` |

条件：通道、区域（可选）、目标类别、置信下限、布防时段（站点时区，可跨午夜）、严重级别、冷却秒数（默认 60）。
- 置信与 Frigate 的模型阈值**分开管理**：我们只做业务侧过滤，不改 Frigate 的检测参数
- 冷却只限制**通知频率**，不丢事件记录（AI-05）
- **停留阈值必须落到检测器**：Frigate 把「停留」实现为区域自己的 `loitering_time`（按检测帧率累计对象在区域内的帧数），并且**用它同时门控 `zones` 与 `entered_zones`**。所以：
  - 一个区域只能有一个停留阈值——第二条不同秒数的停留规则被拒（`rule_dwell_conflict`）
  - 有停留阈值的区域上不能再有「进入」规则（进入会被静默延后到停留时长之后），反向同样拒绝（`rule_enter_on_dwell_zone`）
  - 前端编辑器在提交前就显示该冲突并禁用保存

### 3. 规则命中与预览（AI-06）
- 事件入库时评估规则：命中则记 `event_rule_hits`（哪条规则、命中原因、区域、分数）
- 事件详情展示命中规则与原因；提供「最近检测抓拍 + 目标分数 + 区域 + 触发原因」
- 误报标记：对事件或规则标记误报 + 备注，作为运营反馈（不承诺自动重训模型）

### 4. 去重（AI-05）
- 同一 Frigate 目标、同一规则、一次有效区域进入 → 一个逻辑命中（用上游事件 ID + 规则 ID 唯一约束）
- 后续同一事件的更新只更新命中（分数、结束时间），不新增

## 明确不做

- 实时目标框（AI-05/P1 的实时叠框；PRD 允许首版只做事件抓拍框）
- 越界/计数/人脸/车牌（P2）
- 通知渠道（EVT-05 单独批次；本批的规则命中会写库并展示，通知留批次 4）
- 自动重训、误报自动调参

## 测试覆盖

- **单测**：多边形顶点数/自交/越界校验；布防时段跨午夜判定；比例判定（纯分辨率变化不报、比例变化报、两侧任一未知不报）
- **集成**：区域 CRUD 级联删除；参考几何由服务端从 source test 读取；纯分辨率变化与比例变化两种待校准路径；规则命中（区域进入用 `entered_zones` 匹配）；同一目标只产生一个逻辑命中；误报标记留痕；取帧端点（权限、无检测时 409、字节原样透传、`no-store`）
- **前端**：画布绘制与保存（归一化坐标，不下发参考尺寸）、不足三点不可保存、未校准提示、规则表单（区域规则必须选区域、停留规则带阈值）、事件详情命中原因与误报标记
